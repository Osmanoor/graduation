6.1Post-2024 Small-LLM Arabic Query Enhancement

Needs edit
Task definition. Search arXiv / Google Scholar / ACL Anthology for any paper (2024–2026) testing small (<7B) LLMs for query enhancement on Arabic text. If any exist, the gap claim must be revised. (Source: item 2.7, pt1 — feeds §2.4 / §1.2 gap framing.)

Thesis claims under test

  • §2.4: “none of these studies tested models smaller than 7B for zero-shot query expansion on Arabic text.”
  • §1.2 (resource gap): “Whether small open-source models with 2–8B parameters … can generate useful Arabic query expansions remains an open question.”

Finding — one concurrent counter-example

Macmillan-Scott, Goworek & Özyiğit (2025) — “Generative Query Expansion with Multilingual LLMs for Cross-Lingual Information Retrieval” (arXiv:2511.19325, 24 Nov 2025).
  • QE across 8 languages incl. Arabic on CLIRMatrix + mMARCO, using Aya Expanse 8B, Gemma 3 4B, Gemma 3 12B — so it does use a sub-7B model (Gemma 3 4B) on Arabic, with overlapping model choices to this thesis.
  • Convergent findings: zero-shot best for short queries; CoT/RaR meta-text pollutes BM25; cross-lingual QE helps weakest-baseline languages most.

Why the gap survives (with narrowing)

  • Task mismatch: that paper is cross-lingual IR (query & docs in different languages); this thesis is monolingual MSA Arabic on MIRACL.
  • Concurrency: dated Nov 2025 — legitimate concurrent work, not pre-emptive prior art.
  • No monolingual Arabic small-LLM QE study on MIRACL exists.

Recommendation

Reword §2.4 to “no prior study has evaluated sub-7B models for zero-shot query expansion in monolingual Arabic retrieval; the closest concurrent work applies sub-7B models to cross-lingual Arabic IR.” Cite Macmillan-Scott et al. as independent corroboration; bound §1.2 to “monolingual Arabic.”

6.2Asymmetric Query Expansion in Hybrid Retrieval

Needs edit
Task definition. Search for any work on asymmetric query expansion in hybrid retrieval — applying QE to only one retriever in a fusion setup. If any exist, downgrade the gap claim to “not yet for Arabic.” (Source: P4.2.4, pt6 — feeds §2.4.)

Thesis claim under test

§2.4: “whether applying query expansion asymmetrically to only one retriever in a hybrid system can outperform applying it to both is an open question.”

Finding — closest prior art

Liu et al. (2025) — “Exp4Fuse: A Rank Fusion Framework for Enhanced Sparse Retrieval using LLM-based Query Expansion” (ACL 2025 Findings; arXiv:2506.04760). Runs two routes through the same sparse retriever — raw query & LLM-expanded query — and fuses them with a modified RRF; beats using the expansion alone, reaching SOTA on several benchmarks.

Why the thesis claim is partially (not fully) novel

  • Exp4Fuse = single-retriever query-variant fusion: fuse {sparse(q), sparse(q+exp)}.
  • This thesis = retriever-type asymmetry in a dense–sparse hybrid: fuse {BM25(q+CSQE), Dense(qraw)}.
  • Related but distinct — Exp4Fuse never varies which retriever type gets the expansion in a heterogeneous fusion. It validates the weaker sub-claim (“expansion helps the sparse side”).

Recommendation

Cite Exp4Fuse and reframe: “the asymmetric assignment of expansion across retriever types in a dense–sparse hybrid — and its behaviour for Arabic — has not been studied.” This is stronger: the novelty now has a named, citable nearest neighbour rather than an unsupported “no one has done this.”

Keep
Task definition. Either read enough of Song & Zheng 2024 to defensibly cite it, or replace it with a survey actually read for the QE taxonomy framing. (Source: item 2.14, pt2 — finalizes §2.4 citation.)

Finding

Song, Mingyang & Zheng, Mao (2024), “A Survey of Query Optimization in Large Language Models” (arXiv:2412.17558; last revised Mar 2026).

  • Bib entry is correct — authors, title, URL, year all match. No fix needed for song_2024_a.
  • Taxonomy faithfully represented: the survey defines exactly four atomic operations — Expansion, Decomposition, Disambiguation, Abstraction — an exact match to the thesis (§2.4 / chapter2.tex l.90).

6.4Full Citation Audit

Major — systematic fabrication
Task definition. For every citation: verify the BibTeX key exists in References.bib, the URL resolves, and the cited paper actually says what the thesis claims. (Source: item 2.15, pt2 — explicitly tagged an AI task. 49 bib entries; 38 cited in the compiled thesis.)
Why a “links resolve” check is not enough. Checking that a URL opens a valid repository does not confirm it points to the correct paper or that author/title fields are real. Example: aya_2024’s URL (arXiv 2501.01482) opens fine — to “An unsupervised method for MRI recovery,” not Aya Expanse. Field-level comparison against each source (done here) is required.

6.5SOTA Arabic Retrievers at Submission Time

Needs edit
Task definition. Recommendation 3 lists BGE-M3 and mE5-large as “stronger embedding models.” Check whether these are still SOTA Arabic retrievers at submission time, or whether newer alternatives exist. (Source: P4.5.8, pt4/pt10 — feeds final Recommendation 3.)

Findings (as of mid-2026)

  • BGE-M3 — still defensible. Leads/ties on MIRACL (M3-dense ≈ 67.8 nDCG@10 vs mE5-large ≈ 65.4); the thesis’s own cited Alsubhi 2025 paper independently names BGE-M3 & mE5-large as “the most effective” for Arabic — so the recommendation is grounded.
  • mE5-large — now dated. Beaten on Arabic by Arabic-centric Swan / ArabicMTEB (Alwajih et al., 2024, arXiv:2411.01192): Swan-Large surpasses mE5-large on most Arabic tasks.
  • Strongest open-weight multilingual: Qwen3-Embedding-8B — #1 on the MTEB multilingual leaderboard (score 70.58, released June 2025; arXiv:2506.05176); also Arctic-Embed 2.0, Nomic-Embed-multilingual, Voyage-3.

Recommendation (→ §5.3 Recommendation 3)

  • Keep BGE-M3 as a primary recommendation.
  • Replace bare “multilingual-E5-large” with (a) Qwen3-Embedding-8B (open-weight multilingual leader) and (b) Arabic-centric Swan-Large.
  • Caveat: most scores are MTEB/MMTEB or Arabic STS, not MIRACL retrieval specifically — a small validation run is advisable before adopting.
