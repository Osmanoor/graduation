### 3. Phase 3: Synthesis & Recommendation ✅

**Decision:** Query Expansion with Normalization

**Rationale:**
- Addresses 80% of failure patterns:
  * Spelling errors (40%) → Normalization
  * Named entity variations (35%) → Expansion (variants)
  * Vocabulary mismatch (15%) → Expansion (synonyms)
- Expected impact: 20-45% reduction in failed queries
- Lower cost than HyDE (shorter prompts)
- Better suited for Arabic linguistic issues

**Implementation Approach:**
1. **Step 1: Normalization**
   - Fix spelling errors (missing hamza, alif maqsura)
   - Remove diacritics
   - Standardize spacing

2. **Step 2: Expansion**
   - Add synonyms (آزوت → نيتروجين)
   - Add entity variations (إبن الهيثم → ابن الهيثم)
   - Add related terms (الحجر الاسود → الكعبة، مكة)

**LLM Selection:** Gemini 1.5 Flash (free tier, good Arabic support)

**Alternative:** HyDE (if expansion achieves <15% improvement)

**Documentation:** `research_decisions/qe_technique_selection.md`

## Key Insights

### What We Learned:

1. **Failure Rate is High:** 39% of queries fail with mDPR baseline - significant room for improvement

2. **Arabic-Specific Issues Dominate:** Spelling errors, diacritics, and named entity variations account for 80% of failures

3. **Retrieval vs Ranking:** System retrieves relevant docs (99.4% in top-100) but ranks them poorly (93.4% in top-10)

4. **Query Length Matters:** Short queries perform 41% worse - expansion should help

5. **Evidence-Based Decision:** Query Expansion selected based on quantitative and qualitative evidence, not intuition

### What Surprised Us:

1. **Spelling errors are #1 issue** (40%) - higher than expected
2. **Diacritics cause 25% of failures** - corpus likely has no diacritics
3. **Western topics struggle** (20%) - limited Arabic Wikipedia coverage
4. **Only 5.1% of queries are highly successful** (NDCG≥0.7) - lots of room to improve

---

## Risk Assessment

### Risks Identified:

1. **Expansion May Add Noise:** Mitigation - start conservative (2-3 terms), test multiple lengths
2. **LLM Hallucination:** Mitigation - validate on samples, use temperature=0, fallback to rule-based
3. **API Cost Overrun:** Mitigation - use Gemini free tier, batch queries, cache expansions
4. **No Improvement:** Mitigation - analyze which queries improved/degraded, try HyDE as alternative
