## Key Decisions Made

### 1. Embedding Model Approach ✅ DECIDED
**Decision:** Start with Pyserini pre-built indexes (BM25 + mDPR) for initial baselines.

**Rationale:**
- Fastest path to implement Query Enhancement techniques
- Avoids 12-15 hour embedding time on Colab T4
- mDPR intentionally chosen as "weaker" baseline (not fine-tuned on MIRACL)
- This gives more room for Query Enhancement improvement
- Query Enhancement is our main contribution, not beating already-trained models

**Data Leakage Concern Discussed:**
- E5 and BGE-M3 are trained on MIRACL training set
- High scores on MIRACL are "expected" not "achieved" for these models
- Using mDPR (not fine-tuned) provides a fairer baseline

**Future Plan:**
- After testing QE techniques on mDPR baseline
- Try stronger models (BGE-M3, E5) to see how improvement scales

---

### 2. Dense Baseline Implementation ✅ DECIDED
**Decision:** Use mDPR via Pyserini pre-built FAISS index.

**Rationale:**
- Already implemented in Pyserini
- No embedding time required
- Provides consistent baseline for comparison

---

### 3. Evaluation Pipeline Design ✅ DECIDED
**Decision:** Two-phase approach separating experiment execution from evaluation.

**Pipeline Design:**
1. **Experiment Phase:** Run search → Save results to file
2. **Evaluation Phase:** Calculate metrics from saved results

**Storage Format:**
- Save as IDs only (Query ID + Passage ID) - NOT full passages
- Save top 100 results per query (can extract top 10 later)
- Lightweight storage, easy to manage

**Two Purposes for Saving Results:**
1. **Documentation:** For thesis, to show our work
2. **Context:** For incremental improvement (act as context for Kiro and team)
