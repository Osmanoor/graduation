## Executive Summary

This meeting finalized our research approach, selected our primary dataset, and established clear checkpoints for the graduation project. We transitioned from exploring broad RAG enhancements (GraphRAG, Agentic workflows) to focusing specifically on **Query Enhancement for Arabic RAG systems**.

**Key Decision:** We will adopt a **Technology-oriented approach** - implementing query enhancement techniques on a baseline RAG system and analyzing which problems they solve, rather than pre-selecting specific problems to address.

---

## 1. Research Approach Finalization

### Core Methodology
- **Baseline System:** Simple RAG with standard components (no complex hierarchical structures)
- **Enhancement Layer:** Query Enhancement techniques applied before retrieval
- **Isolation Strategy:** Focus on retrieval metrics (Recall@10, NDCG@10) initially, defer generation evaluation
- **Evaluation:** Measure improvement by comparing baseline vs. enhanced system

### Rationale
Based on Mohamed Rashad's feedback:
- Searching for "the best RAG system" is too complex (multiple components)
- Better to establish a simple baseline and measure improvement from a single layer
- Scalability comes from running more experiments, not architectural complexity
- Hierarchical approaches (RAPTOR, etc.) deemed overly complex for our scope

### Architecture Components
1. **Retriever:** Hybrid approach
   - Dense retrieval: Multilingual embedding model (BGE-m3, Jina AI, or Qwen)
   - Sparse retrieval: BM25 (resource-friendly, good for keywords)
2. **Query Enhancement Layer:** LLM-based or rule-based query transformation
3. **Evaluation:** Retrieval metrics only (initially)

## 2. Dataset Selection

### Primary Dataset: **MIRACL (Arabic subset)**

**Selection Rationale:**
- ✅ **Retrieval-focused:** Ad-hoc retrieval task (not QA generation)
- ✅ **High-quality annotations:** Native speakers, queries written without seeing documents
- ✅ **Natural mismatch:** Queries vs. Wikipedia text creates realistic challenge
- ✅ **Gold passages:** Ground truth for evaluation
- ✅ **Hard negatives:** Documents similar but not relevant (tests precision)
- ✅ **Industry standard:** Widely recognized benchmark
- ✅ **Manageable size:** Suitable for iterative experimentation

**Limitations:**
- ⚠️ MSA only (no dialectical coverage)
- ⚠️ Requires preprocessing of Wikipedia dumps

### Secondary Dataset: **Arabic QA**
- 90,000+ questions
- Difficulty labels (Hard/Easy)
- Can test generalization after primary experiments
- Hard questions: Answer passage not in BM25 top-10 (defines query formulation bottleneck)

### Deferred Considerations
- **Dialectical datasets:** Multi-Native QA (has dialects but smaller)
- **Synthetic data generation:** Concerns about semantic similarity bias
- **Multi-hop datasets:** MINTAKA, ACQAD (complex but translated/synthetic)

## 4. Query Enhancement Techniques (Candidates)

### Technique 1: HyDE (Hypothetical Document Embeddings)
- **Concept:** Generate hypothetical MSA document from query, use for retrieval
- **Arabic Adaptation:** Use Arabic LLM (Jais, AceGPT) for generation
- **Challenge:** Does Arabic LLM hallucination help or hurt?
- **Papers:** HyDE (2022), applicable to both sparse and dense retrieval

### Technique 2: Query Rewriting
- **Concept:** Transform dialect queries to MSA
- **Arabic Adaptation:** LLM-based dialect normalization
- **Challenge:** Requires dialectical dataset for testing
- **Use Case:** Solves morphological/dialectical mismatch

### Technique 3: Query Expansion
- **Concept:** Add synonyms, related terms to query
- **Arabic Adaptation:** Arabic-specific morphology handling
- **Challenge:** Spelling variations (Hamza, Ya, Alif Maqsura)
- **Papers:** Query2doc, QE-RAG

### Technique 4: Query Decomposition
- **Concept:** Break complex queries into sub-queries
- **Arabic Adaptation:** Handle multi-hop reasoning
- **Challenge:** Requires orchestration layer
- **Papers:** Take a Step Back, LevelRAG

### Technique 5: Context Injection
- **Concept:** Provide LLM with knowledge base structure/tree
- **Arabic Adaptation:** Generate hierarchical summary of corpus
- **Challenge:** How to integrate with retrieval evaluation?
- **Inspiration:** Mohamed Rashad's suggestion, coding agents (Agent.md files)

## 8. Key Insights from Discussion

### From Mohamed Rashad Consultation
1. **Simplicity over complexity:** Simple baseline + one layer is better than complex multi-component systems
2. **Knowledge-aware RAG:** LLM should understand knowledge base structure (like Islamic jurisprudence hierarchy)
3. **Hierarchical skepticism:** RAPTOR/tree structures are overly complex for this scope
4. **Scalability through experiments:** More experiments = more contribution, not more architecture
5. **Paper potential:** This approach can yield a good research paper

### From Dataset Analysis
1. **MIRACL superiority:** Best for retrieval-focused research in Arabic
2. **Native formulation matters:** Queries written without seeing documents create realistic challenge
3. **Hard negatives are valuable:** Test system's ability to distinguish similar-but-wrong documents
4. **Size trade-offs:** Larger datasets (Arabic QA) good for generalization, smaller (MIRACL) good for iteration

### From Methodology Discussion
1. **Tech-oriented is safer:** Start with techniques, discover problems they solve
2. **Problem-oriented is riskier:** Requires upfront problem definition and matching dataset
3. **Isolation is key:** Focus on retrieval metrics first, defer generation complexity
4. **Versioning enables iteration:** Track improvements across technique variations
