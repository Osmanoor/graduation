# Generative Relevance Feedback with Large Language Models
**Year:** 2023
**Authors:** Iain Mackie, Shubham Chatterjee, and Jeffrey Dalton
**Venue:** SIGIR '23

## Short Description
The paper introduces Generative Relevance Feedback (GRF), a method that uses Large Language Models (LLMs) to generate synthetic "relevant documents" for query expansion instead of relying on potentially irrelevant documents retrieved in a first pass. By generating various forms of content (keywords, essays, news articles) based on the query and building a probabilistic model from them, GRF mitigates the vocabulary mismatch problem without depending on initial retrieval quality.

## Research Question
How can LLMs be leveraged to improve pseudo-relevance feedback (PRF) for information retrieval, specifically to overcome cases where traditional first-pass retrieval fails to find relevant documents for feedback?

## Main Methodology
1.  **Zero-Shot Generation:** Instead of retrieving documents, the system prompts an LLM (GPT-3 `text-davinci-002`) to generate text relevant to the query.
2.  **Diverse Subtasks:** They define 10 generation subtasks to create diverse context: Keywords, Entities, CoT-Keywords, CoT-Entities, Queries, Summary, Facts, Document, Essay, and News.
3.  **Probabilistic Expansion:** The generated text ($D_{LLM}$) is treated as the feedback set. The model calculates the probability of terms within this generated text and interpolates it with the original query terms using a standard Relevance Model (RM3-like) formula:
    $P_{GRF}(w|R) = \beta P(w|Q) + (1-\beta) P(w|D_{LLM})$
4.  **Retrieval:** The expanded query is run against the index using BM25.

## Dataset & Benchmark
*   **TREC Robust04:** News articles (hard topics).
*   **CODEC:** Complex social science topics (web corpus).
*   **TREC Deep Learning (DL) 19/20:** MS MARCO web queries and documents.
*   **Overlap with MIRACL:** No.

## Key Results
*   **Performance:** GRF significantly outperformed BM25+RM3, achieving 5-19% improvement in MAP and 17-24% in NDCG@10 across datasets.
*   **Best R@1k:** Achieved state-of-the-art recall compared to sparse, dense, and learned sparse models.
*   **Content Type:** Long-form generation (News, Documents, Essays) was 7-14% more effective than short-form (Keywords/Entities).
*   **Format Matching:** Generation styles that matched the target corpus (e.g., News style for Robust04) performed best.
*   **Aggregation:** Concatenating text from *all* generation subtasks yielded the highest performance (2-7% boost over the best single subtask).

## Relevance to Our Project
*   **Applicable to Arabic?** **Yes.** The methodology is language-agnostic. If we have an LLM capable of generating high-quality Arabic text (e.g., GPT-4, or an Arabic-tuned LLaMA), this approach can be applied directly to Arabic queries to solve vocabulary mismatch.
*   **Uses MIRACL?** **No.**
*   **Retrieval metrics reported?** NDCG@10, MAP, Recall@1k.
*   **Feasible for us?** **Maybe.** The retrieval part (BM25) is lightweight. The constraint is the LLM inference. Generating 10 different outputs per query for a large dataset is computationally expensive and slow on Colab. We might need to select only one or two best-performing generation subtasks (e.g., "Facts" or "Essay") or run on a small subset of queries.

## Notes
*   Crucially, this method works well on "hard" queries where standard PRF fails because standard PRF relies on the top-k retrieved docs being relevant. If the initial retrieval is bad, standard PRF adds noise. GRF generates relevance from the LLM's internal knowledge, bypassing the bad initial retrieval.
*   The authors found that explicitly prompting for "Chain of Thought" (CoT) to explain keywords was less effective than simply generating long-form text like essays.
