Project Overview

Project Title & Objective

Title: Improving Retrieval Recall in Arabic RAG Systems via Query Enhancement
Core Hypothesis:
  • Standard retrieval fails in Arabic due to morphological & dialectal gaps
  • Query enhancement can bridge this gap before retrieval
  • Improved queries → Better retrieval → Better RAG performance
Research Question:
Can query enhancement techniques improve retrieval recall for Arabic RAG systems, and which techniques are most effective?

Methodology Options

Dataset Selection: Depends on Approach

If Technology-Oriented → MIRACL
Why MIRACL?
  • Retrieval-focused task
  • High-quality annotations
  • Native speaker queries
  • Gold passages + hard negatives
  • Industry standard benchmark
Statistics:
  • 2.1M Arabic Wikipedia passages
  • ~2,896 queries (train/dev/test)
Limitation: MSA-only (no dialects)
If Problem-Oriented → NativeQA or Specific
Why NativeQA?
  • Dialectal Arabic coverage
  • Real-world query patterns
  • Targets specific Arabic challenges
Or Problem-Specific Dataset:
  • If targeting morphological issues → dataset with morphological annotations
  • If targeting dialects → multi-dialect corpus
  • Custom dataset based on defined problem
Arabic RAG Query Enhancement 9 / 18
Methodology Options

Query Enhancement Techniques (Candidates)

  1. HyDE (Hypothetical Document Embeddings)
    • Generate hypothetical MSA document from query
    • Use generated document for retrieval
    • Works for both dense and sparse retrieval
  2. Query Rewriting
    • Transform dialect queries → MSA
    • Normalize morphological variations
    • LLM-based or rule-based
  1. Query Expansion
    • Add synonyms, related terms
    • Handle Arabic morphology (roots, patterns)
  2. Query Decomposition
    • Break complex queries into sub-queries
    • Handle multi-hop reasoning
First Implementation: HyDE or Query Rewriting (to be decided after baseline)

Challenges & Open Questions

Key Challenges

  1. Dialectical Gap
    • MIRACL is MSA-only
    • Real-world queries often dialectal
    • Mitigation: Defer to Checkpoint 2 or use secondary dataset
  2. Evaluation Granularity
    • Need to understand what improved, not just that it improved
    • Mitigation: Error analysis, query categorization, case studies
  1. Resource Constraints
    • Limited GPU access, API costs, time pressure
    • Mitigation: Use free tiers, prioritize experiments, cache embeddings
  2. Contribution Clarity
    • Unclear if adapting techniques or solving problems
    • Mitigation: Clarify after Checkpoint 1 results
