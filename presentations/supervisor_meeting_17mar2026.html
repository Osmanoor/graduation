Experiment Breakdown

Our Setup: Dataset, Index & Retrievers

Dataset: MIRACL Arabic
  • 2,061,414 Arabic Wikipedia passages (MSA)
  • 2,896 queries (dev set) with relevance judgments
  • Industry-standard multilingual retrieval benchmark
  • Native-speaker annotated (not machine-translated)
Dense Retriever (mDPR):
  • Index: Pyserini pre-built FAISS index (5.47 GB)
  • Encoder: castorini/mdpr-tied-pft-msmarco
  • Query → embedding vector → nearest-neighbor search
  • GPU-accelerated batch encoding (64 queries/batch)
Sparse Retriever (BM25S):
  • Library: BM25S (pure Python, no Java)
  • Arabic stemming (PyStemmer) + NLTK stopwords
  • Query → keyword matching → TF-IDF scoring
  • Parameters: k1=0.9, b=0.4
Evaluation Metrics:
  • NDCG@10: How well are the top 10 results ranked?
  • Recall@10/100: How many relevant docs are in top 10/100?
  • MRR: How high is the first relevant result?
Hardware: Google Colab Pro+ ($58) — T4 GPU (free) for small models, A100 (40GB) for 7-8B models.

Query2Doc: How It Works

Method (Wang et al., 2023): Before retrieval, an LLM generates a pseudo-document that answers the query. This pseudo-document is concatenated with the original query to enrich it with more context and vocabulary.
① Original Query
"ما هي عاصمة السودان" (5 words)
→
② LLM Generates Pseudo-Doc
Prompt: "Write a passage that answers the query. Respond in Arabic only."
Output: ~128 tokens of Arabic context
→
③ Enhanced Query
Original + Pseudo-Doc concatenated
(~200+ words, 9.7x expansion)
Experiment Flow (per model):
  1. Load LLM on GPU (FP16 or 4-bit quantized)
  2. Generate pseudo-docs for all 2,896 queries (~40 min)
  3. Save enhanced queries to .pkl file
  4. Run enhanced queries through Dense retriever (mDPR)
  5. Run enhanced queries through BM25 retriever
  6. Compute metrics & compare vs baseline
What We Varied:
Only the LLM changes — everything else is held constant:
  • Same dataset (MIRACL Arabic)
  • Same prompt
  • Same retrievers (mDPR + BM25S)
  • Same evaluation metrics
  • 10 different LLMs tested
Total: 14+ experiment runs across baselines, first QE, and model comparison.

Phase 1: Analysis

Error Analysis & Technique Selection

Quantitative Error Analysis (N=2,896):
  • 39% failure rate (1,130 queries with NDCG@10 < 0.3)
  • Short queries (1-3 tokens): NDCG = 0.240
  • Long queries (9+ tokens): NDCG = 0.406
  • Short queries achieve only 59% of long query performance
  • Correlation: r=0.125 (p<0.001)
Root Cause: Information poverty in short queries is a validated, dataset-wide driver of retrieval failure.
Technique Selected: Query Expansion
  • Method: Query2Doc (Wang et al., 2023)
  • LLM generates a pseudo-document for each query
  • Pseudo-document concatenated with original query
  • Enriches short queries with contextual information
Why Query2Doc?
  • Directly addresses information poverty
  • Zero-shot (no training data needed)
  • Model-agnostic (swap LLMs easily)
  • Proven effective in English (Wang et al.)

Phase 2: Query Enhancement

Query2Doc: Implementation & First Results

Implementation:
  • Model: Qwen 2.5 3B Instruct (zero-shot, FP16)
  • Prompt: "Write a passage that answers the query. Respond in Arabic only."
  • Output: 128 tokens pseudo-document
  • Expansion ratio: 9.73x average
  • Runtime: ~40 min on Colab T4 (free tier)
Optimizations:
  • Batch processing (8 queries/batch) → 8x speedup
  • Reduced token generation (128 vs 256) → 2x
  • FP16 + eval mode + no_grad
  • Total: 16x speedup

Phase 2: Query Enhancement

Query2Doc + BM25: Opposite Effect

Exp 004: Query2Doc + BM25
Metric Baseline (Exp 002) Enhanced (Exp 004) Change
NDCG@10 0.4621 0.4090 -11.5%
Recall@10 0.5964 0.5384 -9.7%
Recall@100 0.8577 0.8155 -4.9%
MRR 0.4836 0.4342 -10.2%

All metrics declined — opposite of Dense (+8.9%)

Why BM25 declined:
  • Term dilution: pseudo-document's 200+ words overwhelm the original query keywords
  • BM25 relies on exact term matching — added terms reduce weight of important words
  • Missing query repetition: Query2Doc paper recommends repeating original query 5x for BM25
Key Lesson: Query enhancement techniques must be adapted per retriever type. Dense benefits from semantic context; BM25 needs keyword preservation.

Phase 3: Model Comparison

Dropped Models & Lessons Learned

ALLaM-7B (Exp 008)
  • Result: NDCG@10 = 0.2550 (-48.9%)
  • Root Cause: SentencePiece tokenizer leaked special characters into output
  • Unicode marker ▁ appeared in decoded text
  • Preview/alpha model with unstable behavior
  • Lesson: Always verify decoded output for special characters before full runs
GPT-OSS-20B (Exp 009)
  • Result: Dropped before full evaluation
  • Root Cause 1: MoE architecture (32 experts) is 70x slower than dense models via 4-bit quantization
  • Root Cause 2: 3 of 5 sanity queries had severe factual hallucinations
  • English-dominant training = unreliable for Arabic QE
  • Lesson: MoE + 4-bit quantization is impractical for batch query expansion
Other Technical Lessons from Model Comparison:
  • Falcon-H1: Hybrid Mamba architecture has batching bugs — forced batch_size=1, required A100
  • Jais-2: Must use BF16 (Squared-ReLU overflows FP16). Must remove token_type_ids from inputs.
  • Qwen3: Must disable thinking mode (enable_thinking=False). Never use greedy decoding.
  • General: Model-specific temperature settings matter. Architecture dictates batch strategy.

Key Findings

Key Findings from 10-Model Comparison

  1. Model Size Correlates with Dense Performance
    • 2B: +3.7% → 4B: +8-14% → 7-8B: +16-23%
    • Larger models generate higher-quality pseudo-documents
  2. Multilingual > Arabic-Specific (at same size)
    • Aya 8B (+23.5%) > Jais-2 8B (+20.5%)
    • Qwen3-4B (+14.0%) > Falcon-H1 3B (+7.3%)
    • Exception: Jais-2 is best for BM25 (+10.8%)
  3. BM25 Requires Lexically Precise Expansions
    • Only 3 of 9 models improved BM25
    • Arabic-specialized vocab (Jais) helps BM25 most
    • Term dilution is the primary failure mode
  1. Query2Doc Works for Arabic (Zero-Shot)
    • All 8 successful models improved Dense retrieval
    • Best result (+23.5%) exceeds original paper (+2-5%)
    • No Arabic-specific training needed
  2. Temperature 0.1 is Optimal
    • SILMA ablation: temp=0.1 beats temp=0.7 by +2.5%
    • Focused, deterministic outputs work better for retrieval
  3. Generational Improvement Confirmed
    • Qwen3-4B (+14.0%) beats Qwen 2.5-3B (+8.9%)
    • Qwen3-8B (+19.3%) beats Qwen 2.5-7B (+16.4%)
    • Newer model generations improve QE quality

Technical Work

Technical Challenges & Solutions

  1. Java Version Conflict (BM25)
    • Problem: Pyserini needs Java 11, system had Java 21
    • Solution: Switched to BM25S (pure Python)
    • Result: 96% of Pyserini performance, no Java dependency
  2. Slow Query Encoding (mDPR)
    • Problem: Pyserini CPU encoder: 35 min/2,896 queries
    • Solution: GPU batch encoding (64 queries/batch)
    • Result: 5-7x speedup (2-3 min)
  3. Missing Dataset Metadata
    • Problem: MIRACL lacks domain labels
    • Solution: Query-side analysis (length, complexity)
    • Result: Discovered short-query performance gap
  1. Falcon-H1 Batching Bug
    • Problem: Hybrid Mamba architecture fails with batch > 1
    • Solution: Single-query loop on A100
  2. Jais-2 FP16 Overflow
    • Problem: Squared-ReLU exceeds FP16 max (65,504)
    • Solution: BFloat16 precision on A100
  3. ALLaM Tokenizer Corruption
    • Problem: SentencePiece leaked ▁ into output
    • Solution: Model dropped; added sanity checks to pipeline
Infrastructure: Google Colab Pro+ ($58) for A100 GPU access. T4 (free tier) used for smaller models.
